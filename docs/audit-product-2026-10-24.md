# Аудит FLOX — повторный, с упором на универсальность (2026-10-24)

Проверялся HEAD `c87bee5` на живом dev-стеке. Владелец разрешил браузер:
обзор, сети, настройки и тариф просмотрены вживую. Код не менялся.
Предыдущий аудит — `docs/audit-product-2026-10-15.md`; его пункты закрыты
по доске `tools/devpanel`, кроме OPS-1..3, BIZ-3, BIZ-4 ч. 2, INT-2 и CI.

Новый угол: владелец хочет **универсальный трекер**, а не только iGaming
(2026-10-24 формулировки «депозит» заменены на «покупку»). Поэтому
проверялось, готов ли продукт для e-commerce, подписок, приложений и
лидогенерации, в том числе на рынке, где FLOX продаётся в рублях.

---

## A. Executive Summary

**Что изменилось за 9 дней.** Закрыты все P0/P1 из прошлого аудита, кроме
production: уязвимости, валюта по умолчанию у сети, готовый URL постбэка с
проверкой, биллинг с ЮKassa, квоты ClickHouse, роли байеров, OpenAPI,
GDPR (удаление, экспорт, срок IP), rollup отчётов, хранение по тарифу,
транскодинг видео. Код: 68K строк Go, 49K строк тестов, 46K строк TS,
99 миграций Postgres и 25 файлов схемы ClickHouse. Полный прогон Go:
98 пакетов, 1 346 тестов с подтестами, e2e пройден.

**Пять главных рисков**

1. **ffmpeg разбирает чужие файлы внутри воркера с его секретами** (SEC-7,
   High, гипотеза атаки не проверена). `transcode.go` запускает ffmpeg
   без `cmd.Env`, то есть с полным окружением воркера: пароль БД, ключи
   S3, ключи шифрования. Нет `-protocol_whitelist` и принудительного
   демультиплексора. Известный класс атак (HLS-плейлист внутри AVI)
   позволял читать локальные файлы, включая `/proc/self/environ`, и
   ходить в сеть. Код из GAP-1 (моя фаза) — исправить до production.
2. **Рублёвая выручка не попадает в отчёты** (DATA-8, High для рынка
   СНГ). Курсы берутся только у ЕЦБ, а он не публикует RUB, UAH, KZT
   (`docs/fx.md`). Конверсия в рублях остаётся без суммы в USD — та же
   проблема, что была с пустой валютой, только для целой страны. При этом
   тарифы FLOX продаются в ₽. В интерфейсе 8 валют из ~30, рубля нет.
3. **Продукт умеет только «партнёрку»** (UNI-1). Онбординг, сеть, постбэк,
   подсказки предполагают CPA-сеть. Магазину, сервису подписок или
   приложению, которые продают сами, некуда «добавить партнёрскую сеть»;
   статусы показаны как `CPA_ACCEPT`. Переименование слов не сделало
   продукт универсальным.
4. **Нет Google и российских площадок** (UNI-2, UNI-3). Не сохраняются
   `gclid`, `yclid`, `msclkid`; нет выгрузки конверсий в Google Ads и
   Яндекс; пиксели только Meta/TikTok/Snapchat; нет импорта расходов из
   Яндекс Директа и VK Рекламы; шаблоны источников только для push/pop.
5. **Production так и не развёрнут** (OPS-1..3). К этому добавился риск
   REL-2: лимит кликов на IP молча отправляет посетителей на fallback без
   записи. За CDN без `TRUSTED_PROXIES` под лимит попадёт весь трафик, а
   ни алерта, ни счётчика у клиента нет.

**Сильные стороны (подтверждено)**

1. Честная денежная модель с тестами на каждый случай: дедупликация,
   прогрессия статусов, повторное одобрение, сторно.
2. Онбординг постбэка теперь хороший: готовый URL, таблица параметров,
   «Проверить постбэк» без записи, диагностика «повторные покупки без
   txn_id».
3. Биллинг с лимитами, которые никогда не останавливают трекинг, и с
   понятным предупреждением о сокращении хранения.
4. GDPR-база: экспорт организации ZIP без секретов, удаление с отменой
   7 дней, срок хранения IP.
5. Дисциплина: каждая фаза с тестами, мутационными проверками и
   документацией.

**Вывод.** Для iGaming-команд на USD/EUR продукт готов к закрытой бете
сразу после production (OPS-1) и SEC-7. Для «универсального трекера»
сегодня не хватает трёх вещей: путь «свой сайт без партнёрки» (UNI-1),
рубля и других валют СНГ (DATA-8), Google/Яндекс-атрибуции (UNI-2/3).
Какие из них нужны первыми, должны показать интервью BIZ-3.

## E. Data Accuracy

**Подтверждено:** BUG-9 был только в тестах; rollup совпадает с сырыми
строками (`TestRollupReportsMatchRawRows`); retention меняет строки
мутациями, двойного счёта в rollup нет.

**Риски:**

1. [High для СНГ] выручка в RUB/UAH/KZT без USD (DATA-8).
2. [Medium] клики сверх лимита на IP не записаны (REL-2) — отчёт
   занижает клики и не говорит об этом.
3. [Medium] возврат только целиком: DECLINE сторнирует всю выплату;
   частичный возврат заказа не выразить (UNI-4).
4. [Low] событие с датой до cutover, вставленное после backfill, не
   попадёт в rollup — сегодня такого пути вставки нет; новый импорт
   истории (INT-2) должен это учесть.

## F. Security Audit

**Подтверждено:** SEC-8 (stdlib, npm). **Гипотеза, High:** SEC-7.

**Без проблем:** скачивание экспорта только по сессии и `settings.write`,
без токена в ссылке; уведомление ЮKassa перечитывается у ЮKassa;
пользовательские лендинги на своём origin (SEC-5).

**Не проверялось:** эксплуатация SEC-7 на ffmpeg 8.1 (известные атаки
частично закрыты в новых версиях — меры защиты нужны независимо);
мобильная вёрстка; production-логи.

По моим данным, не сверено с официальными сайтами (официальные цены
трекеров — `docs/market-pricing-2026-10.md`).

|---|---|---|---|---|
| Свой сайт без партнёрки | нет | да | частично | да |
| Shopify / WooCommerce | нет | да | нет | CMS-интеграции, CRM |
| Google Ads: gclid, офлайн-конверсии | нет | да | частично | да |
| Яндекс Директ / VK Реклама | нет | нет/частично | частично | да |
| PWA, push, Telegram | да | нет | нет | нет |
| CPA-статусы, LTV | глубоко | есть | частично | есть (через CRM) |

Вывод: в универсальном сегменте FLOX конкурирует с RedTrack (запад) и
сквозной аналитикой (РФ), и проигрывает им по интеграциям. Сильная сторона
FLOX — PWA/push/Telegram и CPA-модель — остаётся нишей арбитража.
Расширяться стоит туда, где эта сила помогает: подписки и приложения с
PWA, лидогенерация.

## J. Final Verdict

1. **Кто сегодня:** iGaming/CPA-команды на push/pop и FB/TikTok через PWA.
2. **Что мешает универсальности:** не слова, а путь без партнёрки, рубль,
   Google/Яндекс.
3. **Три изменения:** SEC-7 (до production); ЦБ РФ как второй источник
   курсов; путь «свой сайт».
4. **Нельзя игнорировать:** SEC-7, OPS-1 с `TRUSTED_PROXIES`.
5. **Нужные данные:** интервью BIZ-3 с вопросом «кто кроме арбитража»;
   production-нагрузка.
