# FLOX: сверка реализации со спецификацией по фазам (2026-10-11)

Источник требований — `docs/FLOX-master-prompt-v3.md`, фазы §9 (0–34, 14.5–14.9,
26.5, 27-COST) и связанные разделы (§26, §39-STICKY, §42, §43, §50, §50-FX,
§53–§59). Каждый пункт проверен по коду, тестам и UI репозитория на коммите
`b8d675f`, а не по отметкам в ROADMAP.

Статусы: ✔ — выполнено; ◐ — частично; ✘ — нет.

## Итог

Все фазы построены, и ядро (маршрутизация, трекинг, атрибуция, конверсии,
постбэки, аналитика, LTV, RBAC, изоляция тенантов, наблюдаемость, деплой)
соответствует спецификации, местами с запасом. Найдено **15 расхождений**; три
из них заметны пользователю сразу:

1. **Пиксели не срабатывают.** Пиксели создаются и привязываются к стрим-сетам,
   но ни tracker, ни worker не отправляют событий в Facebook/TikTok/… — фазы
   13 и §29 пиксельной части по сути не доделаны.
2. **В списке кампаний нет метрик** (Clicks/Conversions/Revenue/Spend/Profit/
   ROI, §20). Из-за этого цель «Campaigns Table» у кастомных метрик (§30.5)
   предлагается как доступная, но метрика там нигде не появится.
3. **Постлендинги не показываются трекером** (уже в ROADMAP): этап
   настраивается в потоке, но POSTLANDING_VIEW/CLICK не генерируются, и
   измерения `postlanding` в отчётах нет.

## Закрыто после сверки

- **2026-10-11 — пиксели (расхождение 1).** Server-side отправка в
  Facebook CAPI, TikTok Events API, Snapchat CAPI и generic URL из worker
  через очередь `pixel_deliveries`: CPA-события из транзакции конверсии,
  PWA_INSTALL из потока событий. Twitter/X не отправляет (нужен OAuth
  1.0a) и больше не выбирается. `docs/pixels.md` «Sending».
- **2026-10-11 — метрики в списке кампаний (расхождение 2).** Колонки
  Clicks, Conversions, Revenue, Spend, Profit, ROI за выбранный период (по
  умолчанию 30 дней, часовой пояс организации) из `/analytics/report` по
  измерению `campaign`; кастомные метрики с целью «Campaigns Table»
  выводятся колонками. Без расхода — «—». Copy tracking URL в строке
  остаётся в ROADMAP.
- **2026-10-13 — постлендинги (расхождение 3).** Трекер ведёт посетителя
  на постлендинг вместо оффера (сразу после клика, после внутреннего
  лендинга, после запуска PWA или «продолжить без установки») и пишет
  POSTLANDING_VIEW; макрос `{next_url}` в URL постлендинга — подписанная
  ссылка `/pc/`, она пишет POSTLANDING_CLICK и уводит на оффер.
  `postlanding_id` на всех событиях пути и конверсиях (ClickHouse
  `schema/016`), измерение `postlanding` в отчётах, «Посмотреть статистику»
  в списке постлендингов. `docs/postlanding.md` «Serving visitors».
- **2026-10-13 — измерение `network` (расхождение 4).** Клик несёт сеть
  оффера, на который ушёл (ClickHouse `schema/017`, трекер в момент клика;
  дальше по подписанной ссылке на LAND_*/PWA_*/POSTLANDING_*), конверсия —
  сеть постбэка. История заполнена один раз по `offer_id`. Измерение
  `network` в отчётах, «Посмотреть статистику» в списке сетей.
  `docs/analytics-report-api.md`.
- **2026-10-13 — Push (расхождение 5).** Раздел Push в меню: подписки из
  установленных PWA (переключатель у PWA, страница запроса при запуске,
  NOTIFICATION_REQUEST/SUBSCRIBE/DECLINE), рассылки «отправить сейчас» на
  сегмент с очередью в worker через Web Push (VAPID), счётчики
  доставлено/ошибки/открыто, NOTIFICATION_CLICK и UNSUBSCRIBE. Права
  `push.read`/`push.write`. Без отложенных и триггерных рассылок и без
  push-метрик в отчётах. `docs/push.md`.
- **2026-10-13 — расходы: страна и CSV (расхождение 6).** Расход можно
  вводить по стране (`cost_entries.country`, миграция 00071); день —
  либо одна сумма, либо разбивка по странам. Отчёт по измерению `country`
  получает расход, если весь расход периода разбит по странам, иначе «—».
  Импорт CSV на вкладке «Расходы» кампании, целиком или никак, с ошибками
  по строкам. Синхронизация не трогает дни, разбитые вручную.
  `docs/cost-ingestion.md`.
